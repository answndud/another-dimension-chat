# 프로토콜·응용프로그램 인터페이스 개요

작성 기준: 2026-08-23 개편 완료 후 현재 코드 상태

## 1. 로컬 bridge API (daemon → browser)

모든 경로는 `/local-api/` 접두사를 사용하며 session cookie + CSRF(변경 요청) + Origin +
Host + UI version 검증을 통과해야 한다.

### 상태·신원

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/local-api/status` | daemon 현재 상태 |
| GET | `/local-api/identity` | 계정·기기 식별자 |
| POST | `/local-api/setup/profile` | 최초 프로필 생성 |

### 초대·페어링

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/local-api/invites` | 일회성 초대 생성 (그룹 확장 가능) |
| POST | `/local-api/invites/consume` | 초대 코드 소비 + relay 검증 |
| POST | `/local-api/pairing/auto-sync` | rendezvous에서 peer key package 읽기 |
| POST | `/local-api/pairing/approve` | 승인 + welcome 생성·전송 |
| POST | `/local-api/pairing/complete-session` | welcome 받아 그룹 join |
| POST | `/local-api/pairing/verify-safety` | safety number 확인 |

### 연락처·대화

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/local-api/contacts` | 연락처 목록 |
| GET | `/local-api/conversations` | 대화 목록 |
| POST | `/local-api/messages/list` | 메시지 히스토리 조회 |
| POST | `/local-api/session/send` | 메시지 암호화·전송 준비 |
| POST | `/local-api/session/receive` | 수신 메시지 복호화 |
| POST | `/local-api/session/add-member` | 그룹 멤버 추가 (`key_packages: string[]` 지원) |
| POST | `/local-api/session/join` | welcome으로 MLS group join |

### 전달

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/local-api/delivery/post` | 암호문을 relay inbox에 제출 |
| POST | `/local-api/delivery/sync` | relay inbox에서 수신·복호화 |
| POST | `/local-api/delivery/retry` | 실패한 전달 재시도 |

### WebSocket 실시간 이벤트 (P2 완료)

```
GET /local-api/events  (HTTP upgrade: websocket)
```

- **인증**: HTTP API와 동일한 session cookie + Origin + Host + UI version 검증을
  upgrade 전에 통과해야 한다. 실패 시 401.
- **push payload**: `{"type":"messages_updated"}` — maintenance tick에서 새 메시지가
  처리되면 모든 subscriber에 broadcast.
- **heartbeat**: 20초마다 ping frame.
- **재연결**: 클라이언트가 close 감지 시 3초 후 재연결. 재연결 성공 시 활성 대화 sync.

## 2. relay API (daemon ↔ relay)

### 초대 rendezvous

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/invite-codes/public` | signed invite 등록, 코드 발급 |
| POST | `/api/v1/invite-codes/consume` | 코드 소비 + invite + receipt 반환 |
| POST | `/api/v1/invite-codes/pairing-response` | key-package/welcome 게시 또는 읽기 |

pairing-response는 invite당 `pairingResponses` 배열을 유지한다 (P5 완료). 그룹 소유자는
여러 멤버의 key-package를 순차 게시하고, 각 멤버에게 welcome을 배열에 추가할 수 있다.

### inbox·blob

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/v1/inbox/{capability}` | opaque envelope 제출 |
| GET | `/api/v1/inbox/{capability}` | envelope 목록 조회 |
| POST | `/api/v1/inbox/{capability}/ack` | 처리 완료 envelope 삭제 |
| POST | `/api/v1/blobs/{id}` | 첨부 blob 청크 업로드 |
| GET | `/api/v1/blobs/{id}` | 첨부 blob 다운로드 |

## 3. 오류 코드 매핑

브라우저 `errors.ts`에서 daemon 오류 코드를 한국어 사용자 메시지로 변환한다.

| 코드 | 의미 |
|---|---|
| `session_invalid` | 세션 만료·잠김 — 재인증 필요 |
| `pairing_not_ready` | 페어링이 아직 승인되지 않음 |
| `relay_capability_expired` | relay 자격 만료 — 재설정 필요 |
| `relay_unavailable` | relay 연결 실패 |
| `invalid_invite` | 초대 코드 잘못됨·만료 |
| `contact_blocked` | 차단된 연락처 |
| `duplicate_delivery` | 중복 전달 감지 |

## 4. 데이터 형식

메시지 평문은 UTF-8 JSON으로 daemon 내부에서 관리되며, hex encoding으로 전달된다.
MLS 암호문은 OpenMLS wire format이며 relay에는 `ADENV1.` 접두사의 opaque envelope로만
노출된다.
