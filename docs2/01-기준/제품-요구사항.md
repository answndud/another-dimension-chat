# 제품 요구사항

작성 기준: 2026-08-23 개편 완료 후 현재 코드 상태

## 1. 문서 목적

이 문서는 Another Dimension Chat의 현재 제품 경계와 사용자에게 제공해야 하는
행동을 정의한다. 암호학적 안전성을 보증하는 감사 보고서가 아니며, 구현되지 않은
기능을 로드맵으로 위장하지 않는다. 구현·문서·배포 설정이 충돌하면 현재 코드와
루트의 `README.md`, `SECURITY.md`, `reference/SUPPORT_MATRIX.json`이 우선한다.

## 2. 제품 정의

Another Dimension Chat은 각 사용자의 Mac에서 Rust daemon을 실행하고 Chromium으로
로컬 UI에 접속하는 암호화 메신저다. daemon이 계정·기기 키, OpenMLS 상태, 암호화
저장소, 전달 상태를 소유한다. relay는 사용자가 직접 운영하거나 신뢰 경로를 확인한
것을 사용하며, 메시지 평문을 해석하지 않는 전달 경로로 제한한다.

제품의 핵심 약속은 "중앙 trusted server가 없어도 된다"이지 "서버나 네트워크가 아무
정보도 보지 못한다"가 아니다. IP, 연결 시각, 크기와 같은 메타데이터 및 감염된
단말의 화면·입력은 보호 범위 밖이다.

## 3. 대상과 사용 모드

| 모드 | 대상 | 현재 판정 |
|---|---|---|
| `development` | 개발·로컬 확인 | 허용 |
| `private-trusted` | 본인과 신뢰하는 지인 | 제한적으로 준비 |
| `public` | 불특정 다수 | 독립 검토 전 금지 |
| `high-risk-disabled` | 고위험 기자·취재원 | 항상 비활성화 |

고위험 사용자를 대상으로 한 안전성 승인은 아직 존재하지 않다. 이 문서의 기능 요구를
충족했다는 사실만으로 실제 고위험 통신을 허용하지 않는다.

## 4. 제품 범위

### 포함

- 전화번호·이메일 없이 생성되는 로컬 계정과 기기 신원
- 운영체제 난수로 생성되는 프로필 암호문구의 표시·오프라인 보관
- 1회성·만료형 초대 코드와 signed invite
- 별도 신뢰 채널에서 대조하는 safety number
- 연락처 승인 후의 OpenMLS 기반 세션 (1:1 및 다중 멤버 그룹)
- **실시간 메시지 수신** — daemon WebSocket push (`/local-api/events`)로 새 메시지 도착 시 즉시 UI 반영. 연결 끊김 시 자동 재연결(3초 간격)하고 상태 배너로 사용자에게 알림.
- 텍스트 메시지, 로컬 transcript, 전달 상태
- 청크 단위 암호화 첨부파일과 bounded relay blob
- 잠금, 복구 export/import/rotate, 기기 확인과 폐기
- **React 19 + TypeScript + Vite 기반 웹 UI** — 컴포넌트 구조(`screens/`, `components/`, `hooks/`, `lib/`), 타입 안전한 daemon bridge, 실시간 연결 상태 배너
- **그룹 초대 UI** — 연락처 목록에서 복수 멤버 선택 후 그룹에 추가 (`GroupInvite.tsx`)
- 사용자가 실행하는 relay와 localhost 브라우저 UI

### 의도적으로 제외

전화번호 로그인, 이메일 로그인, searchable username, 중앙 contact discovery, 중앙
메시지 서버, 푸시 알림, 클라우드 백업, 음성·영상 통화, 기본 P2P, 익명성·Tor·검열
저항성, 자동 업데이트, 다중 플랫폼 지원은 현재 v0.1 범위가 아니다.

## 5. 핵심 사용자 흐름

1. 사용자가 각자의 Mac에서 daemon 프로필을 초기화한다.
2. 양쪽이 접근 가능한 relay를 준비하고 relay origin·공개키·TLS pin을 별도 신뢰 채널로
   확인한다.
3. 한쪽이 일회성 초대를 생성하고 코드를 별도 채널로 전달한다.
4. 상대가 코드를 소비하면 daemon이 서명·만료·relay binding을 검증한다.
5. 양쪽이 safety number 전체를 독립 채널에서 대조한다.
6. 사용자가 연락처를 승인한 뒤 OpenMLS 세션을 만들고 메시지를 교환한다.
7. 그룹 소유자는 추가 멤버의 key package를 batch add-member로 그룹에 초대할 수 있다.
   각 멤버는 welcome을 받아 그룹에 join한다.
8. 계정·기기·relay binding이 바뀌면 전송을 멈추고 재확인을 요구한다.

## 6. 실시간 UX 요구사항 (P2 완료)

- daemon이 `/local-api/events` WebSocket endpoint를 제공하며, session cookie +
  Origin + Host + UI version 검증을 통과해야 연결된다.
- maintenance tick에서 새 메시지가 처리되면 연결된 클라이언트에 `messages_updated`
  payload를 push한다.
- 클라이언트는 수신 즉시 활성 대화를 동기화하고 UI를 갱신한다. polling 폴백 없이
  WebSocket이 유일한 실시간 경로다.
- WebSocket 끊김 시 `reconnecting` 배너를 표시하고 3초마다 재연결을 시도한다.
  재연결 성공 시 `online` 배너로 전환된다.

## 7. 완료 기준

- 장기 키와 MLS 상태가 브라우저 저장소에 남지 않는다.
- 잠금 상태에서 메시지·첨부·신원 API가 평문을 반환하지 않는다.
- 초대는 만료·1회 사용·서명 검증을 모두 통과해야 소비된다.
- 확인되지 않은 신원 변경은 fail-closed로 메시지 전송을 중단한다.
- relay에는 opaque envelope와 암호화 blob만 저장되고 크기·개수·빈도가 제한된다.
- 재시작·중복 전달·잘못된 입력에서 데이터 무결성과 상태 전이가 깨지지 않는다.
- release archive는 개인 키·프로필 데이터·로그·빌드 캐시를 포함하지 않는다.

## 8. 비기능 요구사항

- 기본 바인딩은 loopback이며 원격 노출은 명시적 운영 설정이 필요하다.
- 기능 실패는 조용히 허용하지 않고 사용자에게 재검증·재시작·복구 조치를 안내한다.
- 브라우저 번들은 Vite로 빌드된 정적 asset이며, 외부 CDN·Node.js 서버 런타임 없이
  daemon이 직접 서빙한다.
- 기본 검증은 짧은 focused check를 사용하고, 빌드 캐시는 bounded 정책을 따른다.
- 민감정보는 로그·스크린샷·지원 보고서·명령행 인자에 넣지 않는다.

## 9. 비주장

현재 제품은 독립 보안 감사, 고위험 통신 승인, 완전한 메타데이터 보호, 감염된 단말
방어, 안전 삭제, 무중단 전달을 주장하지 않는다. 이 제한은 제품 요구사항의 실패가
아니라 배포 모드를 결정하는 안전 경계다.
