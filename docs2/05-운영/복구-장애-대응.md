# 복구·장애 대응

작성 기준: 2026-08-23 개편 완료 후 현재 코드 상태

이 문서는 "문제를 숨기지 않고 안전한 상태로 멈추는 것"을 우선한다. 복구가 항상 가능하다고
약속하지 않으며, 손상된 원본을 보존한 뒤 별도 directory에서 검증한다.

## 1. 분류

| 상황 | 우선 행동 |
|---|---|
| local URL 노출 | daemon 중지, session 무효화, 새 data directory로 회전 |
| relay capability 노출 | relay 중지, 기존 data directory 보존, 새 relay identity로 시작 |
| invite 코드 노출 | 만료·소비 상태 확인, 미사용이면 폐기 후 새 초대 생성 |
| safety number 변경 | 승인·전송 중지, 별도 채널에서 재대조 |
| release key 의심 | 배포 중지, fingerprint 공지·교체·revocation 절차 시작 |
| store corruption | 원본 복사 보존, `doctor`/`recovery inspect`, 별도 복구 경로 |
| relay 장애 | 재시작 전 data directory와 queue 파일 백업 |
| profile passphrase 분실 | 우회하지 않음, 오프라인 recovery 사용 여부 확인 |

## 2. 정상 종료

먼저 UI에서 lock하거나 launcher의 stop을 사용한다. 프로세스가 종료되기 전까지 새 메시지·
첨부를 만들지 않는다.

## 3. recovery export/import

export는 암호화된 profile snapshot을 offline 매체에 저장한다.

```sh
./bin/another-dimension-daemon recovery export \
  --data-dir "$HOME/.local/share/another-dimension/alice" \
  --output /Volumes/OFFLINE/alice.adrecovery

./bin/another-dimension-daemon recovery inspect \
  --input /Volumes/OFFLINE/alice.adrecovery
```

import 전에는 별도 임시 directory에서 파일 형식·version·profile ID를 확인한다. 기존 운영
directory에 바로 덮어쓰지 않는다.

## 4. 키·capability 회전

capability는 bearer secret이므로 노출 시 "로그에서 지웠다"만으로 회복되지 않는다. 기존
relay를 중지하고, 새 data directory·새 key·새 capability로 시작한 뒤, 각 연락처에 새 relay
binding과 safety number 확인을 다시 요청한다.

## 5. 사고 기록

사고 기록에는 다음만 남긴다: 감지 시각과 사용한 release revision, 영향받은 자산의 종류(실제
secret 값은 제외), 취한 조치와 결과, 남은 위험과 후속 작업.
