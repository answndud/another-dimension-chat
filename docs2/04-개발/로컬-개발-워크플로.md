# 로컬 개발 워크플로

작성 기준: 2026-08-23 개편 완료 후 현재 코드 상태

## 1. 작업 범위 확인

현재 제품 경로는 `apps/web`(React+TS+Vite), `apps/daemon`, `apps/relay`,
`apps/tools`다. legacy Tauri/native/Olm 경로와 vanilla JS 파일을 새 기능의 기반으로
되살리지 않는다. 작업 시작 전에 변경이 신원·암호·bridge·relay·release 중 어느 경계를
건드리는지 한 줄로 적는다.

## 2. 의존성 없이 빠른 확인

```sh
git status --short
cargo check --workspace --release --locked --offline
cd apps/web && ./node_modules/.bin/tsc && ./node_modules/.bin/vite build
bash -n scripts/*.sh
git diff --check
```

웹 빌드는 Vite 기반이며 `apps/web/node_modules`가 필요하다. 최초 1회만
`npm install --prefix apps/web`을 실행하고 이후 offline으로 재사용한다.

## 3. 개발 실행

```sh
# relay 시작
AD_RELAY_DATA_DIR=.local/relay AD_RELAY_PORT=1422 \
  cargo run -p another-dimension-relay --offline

# daemon 시작 (web UI 자동 서빙)
printf '%s' "$(cat /secure/offline/profile.passphrase)" | \
  cargo run -p another-dimension-daemon -- \
  serve --data-dir .local/alice --port 1420 \
  --ui-dir apps/web/dist --open
```

웹 프론트엔드를 수정하는 경우:

```sh
cd apps/web
./node_modules/.bin/tsc        # 타입 검사
./node_modules/.bin/vite build # dist 산출물 생성
```

사용자별 data directory와 relay directory를 분리한다. 출력되는 URL·capability는 셸
history, 로그, 화면 공유에 남기지 않는다.

## 4. React 컴포넌트 작업 규칙

- 상태는 `useDaemon.ts` hook에서 관리한다. 컴포넌트에 daemon bridge 참조를 직접
  import하지 않고 props로 전달한다.
- WebSocket 구독은 `useWebSocket.ts`에서만 수행한다. 다른 hook이나 컴포넌트에서 직접
  `new WebSocket()`을 만들지 않는다.
- daemon API 호출은 반드시 `lib/daemon-bridge.ts`의 타입 안전 함수를 사용한다. raw
  `fetch`를 컴포넌트에서 호출하지 않는다.
- 오류 표시는 `errors.ts`의 매핑을 사용한다.
- vanilla JS 파일(`daemon-controller.js` 등)은 legacy이므로 수정하지 않는다.

## 5. Rust·용량 정책

기본 빌드 환경은 다음과 같다.

```sh
export CARGO_BUILD_JOBS=2
export CARGO_INCREMENTAL=0
export CARGO_TARGET_DIR="$PWD/.build-cache/cargo-target"
```

한 프로젝트 안에 `target/`, 여러 profile별 target, `.vite/`, 임의 cache를 만들지 않는다.
`.build-cache/cargo-target`은 재생성 가능한 산출물이며 필요할 때 크기를 확인하고 정리한다.

## 6. 변경 단위

보안 경계 하나를 작은 기능 단위로 바꾼다. 같은 변경에 UI 재설계·protocol 변경·release
스크립트 수정을 섞지 않는다. **phase가 끝나면 반드시 commit한다** (사용자 지시).

새 crate를 추가하기 전에 표준 library나 기존 module로 해결할 수 있는지, binary와 cache
크기가 얼마나 늘어나는지 확인한다.

## 7. 문서 갱신

현재 동작을 바꾸면 `docs2/`와 `README.md`, `SECURITY.md`, 필요한 reference를 함께 갱신한다.
문서에는 "구현됨", "내부 smoke로 확인됨", "외부 증거 필요"를 구분한다. 실행하지 않은
matrix나 독립 검토를 완료로 쓰지 않는다.

## 8. 종료 전 확인

```sh
git status --short
du -sh . ./.build-cache ./.??* 2>/dev/null | sort -h | tail
```

민감한 profile·passphrase·log가 diff에 들어가지 않았는지 확인하고, 재생성 가능한 산출물은
commit하지 않는다.
