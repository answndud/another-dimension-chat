# 검증 전략

작성 기준: 2026-08-23 개편 완료 후 현재 코드 상태

## 1. 계층

| 단계 | 명령 | 확인하는 것 |
|---|---|---|
| 정적 | `cargo fmt --check`, `bash -n scripts/*.sh`, `git diff --check` | 형식·스크립트·diff 오류 |
| 경량 | `cargo check --workspace --release --locked --offline` | workspace compile 경계 |
| web | `cd apps/web && tsc && vite build` | 타입 안전·React 빌드 성공 |
| focused test | `cargo test -p another-dimension-daemon websocket` 등 | 변경 영역 회귀 |
| focused smoke | `scripts/smoke_p0.sh` | 3 daemon/relay의 핵심 로컬 흐름 (P0+P5) |
| release | `scripts/verify_full.sh --release` | release binary·web·launcher·smoke 통합 |

## 2. 권장 순서

일반 변경은 정적→경량→변경 영역 focused smoke 순서로 끝낸다. protocol, storage, bridge,
relay, release 중 여러 경계를 함께 건드린 경우에만 `verify_full.sh`를 한 번 실행한다. 같은
revision에 성공한 명령을 의미 없이 반복하지 않는다.

## 3. 영역별 최소 검증 조합

| 변경 영역 | 최소 검증 |
|---|---|
| web만 (TSX/hooks) | `tsc && vite build` + shell syntax |
| bridge/session (`bridge.rs`, `http_errors.rs`) | `cargo check` + local smoke |
| WebSocket (`websocket_events`) | `cargo test -p another-dimension-daemon websocket` + web build |
| relay 제한 (`apps/relay`) | `cargo check` + relay API focused smoke |
| MLS/storage/attachment | `cargo check` + P0 smoke |
| pairing state machine | `cargo test -p another-dimension-daemon pairing` + P5 smoke |
| release script | release verification + archive secret/size 확인 |
| 문서만 변경 | 링크·diff·문법 확인 |

## 4. 무엇을 증명하지 않는가

자체 smoke는 독립 암호 review, 악성 OS·browser, metadata anonymity, 고가용성, 실제 운영
signing trust, 다른 OS/browser 호환성을 증명하지 않는다. `cargo test`의 전체 통과도 이
항목들을 대체하지 않는다.

## 5. 실패 대응

첫 실패의 명령과 짧은 로그만 보존한다. cache를 삭제하고 무작정 재시도하지 않는다. 원인을
compile·환경·runtime·상태 데이터로 분류한 뒤 최소 범위에서 수정한다. **HTTP 에러 디버깅 시
반드시 응답 body까지 출력해 원인을 한 번에 파악한다** (grep으로 status code만 반복 추적하지
않는다 — 과거 P4 디버깅 교훈).

민감한 URL·capability·평문을 로그에 남기지 않는다.

## 6. 결과 기록

실행한 명령, revision, 환경, 결과만 짧게 기록한다. "통과"는 명령이 통과했다는 뜻으로 쓰고
제품 전체가 안전하다는 표현으로 확장하지 않는다.
